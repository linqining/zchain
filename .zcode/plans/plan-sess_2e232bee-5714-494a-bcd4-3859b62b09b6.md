# 控制逻辑入 AIR + 移除 mirror 双状态模式

## 现状诊断（探索结论）

1. **AIR 是 preimage→postimage 行约束**：`src/texas_canonical_air.rs`（14,937 行，29 个 transition kind，890 条约束）逐行验证 `CanonicalTransitionWitness{pre, post}` 的关系（下注算术、轮转、收注、盲注、rake、超时级联），但 postimage 由宿主计算，AIR 只验不导。规范级联（`normalize_until_blocked`，state_machine.rs:2646）在单次 dispatch 内连跳多条街，折叠成一对 pre/post——违反单街收注投影规约（dev_bot 1BB all-in 分歧的根因，现用 10×BB buy-in 规避）。
2. **mirror 双状态模式**：游戏层 `Table`（texas/src/pokergame/table）与 VM 镜像（texas/src/starknet/{shadow,mirror}.rs）两套状态，散落同步补丁点：`apply_betting_view` / `sync_rejected_view` / `last_rejected_view` / game_loop 手动轮转 / `advance_to_next_phase` 相位猜测（`!view.in_betting && !view.hand_over`）。失步 bug 族全部落在这条缝上（2026-09-13 reveal 死锁、09-07 多发一张公共牌、09-14 双推进活锁）。
3. **真实桌 canonical 归档生产者未接线**：hooks.rs:177 `appchain_hand_proof = None` 硬编码，只有 scenario_tests 夹具调 `prove_canonical_tagged_batch`。
4. **pokergame 测试缺口**：all-in 路径、下注合法性、相位转换单测、reveal 超时级联、多池分派、座位管理、视图派生语义均无直接覆盖。

## 决策（已确认/采用）

- **fail-closed**：不可证明（无镜像）的手不允许开局，`fold_local/call_local/check_local/raise_local` 删除，规则引擎只留 VM 一份。
- **视图层采用单一同步入口**（推荐项）：保留 summary 渲染缓存，所有写路径收敛到唯一 `refresh_from_vm()`；全派生读路径作为后续可选清理。

## Stage 0 — pokergame 测试基线（先行，独立可合并）

在 `texas/src/pokergame` 内按仓库惯例新增内联 `#[cfg(test)]` 模块：

1. **betting 规则测试**（table/betting.rs 或新文件 `betting_rules_tests`）：
   - `validate_fold/call/check/raise` 合法性矩阵（越权座位/金额不足/未轮到/min-raise 违规）
   - `handle_allin` 两分支：raise 路径（total_bet > call_amount）与 call 路径（cap at stack）
   - `is_betting_round_complete`：BB option 不被跳过、all-in 座位排除、fold 不提前完成
   - `check_betting_timeout`：超时 fold；轮到不可行动座位时跳过并重置计时
2. **相位测试**（table/phases.rs）：`advance_to_next_phase` 街道阶梯 PreFlop→Flop→Turn→River→Showdown（每街发牌数 + reveal 窗口开启）；`reject_during_reveal_ceremony` 兜底；`set_blinds` 单挑定位 + 盲注后全员 all-in（`has_actionable_player`=false → turn=None）。
3. **all-in 全手 e2e**（table/full_hand_tests.rs 风格）：真洗牌/reveal + mirror 路径 + all-in runout 收尾。1BB 盲注 all-in 场景先以 `#[ignore]` 挂上作为 Stage 2 回归锚点（当前会暴露投影分歧）。
4. **reveal 级联测试**（table/reveal.rs）：`on_reveal_complete` 相位推进、`on_reveal_timeout` 升级路径、`materialization_broken`、`is_benign_reveal_error`。
5. **多池分派测试**（table/pot.rs 扩展）：`determine_side_pot_winners` 多层池赢家、平分池、odd-chip、弃牌者贡献不入资格。
6. **座位管理测试**（table/seat_mgmt.rs）：中途离场退款、kick、断线→sitting_out、重连、rebuy。
7. **视图语义 pin 测试**：`apply_betting_view` 派生规则（hand_over 跳过 stack 同步、fold_win_pot 取终局前底池、相位联锁触发 advance_to_next_phase）、`sync_rejected_view`——重构前钉住现语义，Stage 1 改写后同名测试改断言新入口。

验收：`cargo test -p texas` 全绿（新增约 25–35 个用例）。

## Stage 1 — 单一状态化：VM 权威 + 移除 mirror 模式

1. **fail-closed 落地**：删除 `fold_local/call_local/check_local/raise_local`；`mirror_try_bet` 返回 None（无镜像）→ 动作直接拒绝；`bootstrap` 失败或 `TEXAS_SHADOW_PROVER=0` → 不开局（从"可玩不可证"改为"不可玩"）。`BettingRound` 本地账本（pokergame/betting.rs）降级为纯展示派生（VM 视图填充）。
2. **单一同步入口**：新增 `Table::refresh_from_vm(&mut self)` 合并 `apply_betting_view` + `sync_rejected_view`；betting.rs 四个 handle_* / reveal.rs / seat_mgmt / 超时路径统一为「dispatch → 无论成败 refresh_from_vm → 返回结果」；删除 `last_rejected_view` 字段与 shadow.rs 中的存储逻辑。
3. **事件驱动仪式**：VM dispatch 返回的 events（`RoundAdvanced` / `BettingRoundStarted` / reveal 窗口开启 / 手牌终局）成为游戏层客户端仪式的唯一触发器：`advance_to_next_phase` 重写为事件处理函数（收到 RoundAdvanced 才发下一街牌 + 开 reveal 窗口）；game_loop.rs 中手动 turn 轮转与基于 `is_betting_round_complete` 的相位推断删除（保留只读展示用途）。
4. **结算单源**：结算只从 VM `pre_settlement` 快照 + `derive_settlement_plan`（appchain/exit.rs 已有投影）取数；`pot.rs` 评估器降为展示用途；`cross_check_snapshot`/`cross_check_deltas` 简化为守恒断言（零和 + 抽水上限），删除双实现一致性门（`finish().issues` 中的对账项相应收缩）。
5. **shadow.rs/mirror.rs 重组**：合并为单一 `VmSession` 模块（保留 TableMirror 机械层：dispatch 包装、ProveTask 收集、reveal canonical 重排、pre_settlement 快照、deck 注入引导）；"mirror/shadow" 命名与文档注释清除。

涉及文件：table/{mod,betting,phases,reveal,seat_mgmt,pot,lifecycle}.rs、socket/game_loop.rs、starknet/{shadow,mirror,hooks,prove_log}.rs。Stage 0 的 pin 测试同步改写到新入口。

## Stage 2 — 控制逻辑入 AIR：micro-step witness 链 + 真实归档生产者

1. **poker_l1 捕获规范化轨迹**：`normalize_until_blocked_in_place` 每步已有 `before.clone()`（原子回滚用）——在证明 armed 时保留为 `NormalizationTrace { steps: Vec<(NormalizationStep, pre_table, post_table)> }`（上限 32，复用现有 clone，不新增热路径成本），挂到 `DispatchOutput`。
2. **根 crate 新增 witness 生产者**（新模块，如 `src/canonical_dispatch_trace.rs`）：`(命令 pre, NormalizationTrace)` → `Vec<CanonicalTransitionWitness>`：命令本身一行（Fold/Check/Call/Raise/SubmitRevealTokens…）+ 每个 micro-step 一行（AdvanceRound=19 / EndWithoutShowdown=21 / RevealComplete / ShuffleComplete…），call_seq 连续、pre/post 链式咬合。**all-in 连跳变为多行单街链，PotCollected 投影分歧结构性消除**。
3. **texas 结算接线**：live mirror（VmSession）累积每手全部 dispatch traces；结算时 `prove_canonical_tagged_batch` → `ArchivedCanonicalTaggedProof` → 填入 hooks.rs 的 `appchain_hand_proof`（替换硬编码 None，关闭 BLOCKERS B6）。Starknet legacy 证明路径保留为回退不动。
4. **约束完备性审计**：逐 kind 的 postimage 字段级 checklist（对照 texas_canonical.rs `validate_*` 镜像函数产出文档表），显式标注残留宿主见证字段；密码学方程（BG shuffle/DLEQ/reveal token）维持 native 验证（Plan D 既定边界，不入 AIR）。
5. **dev_bot 去除 10×BB workaround**：恢复 1BB all-in 场景真实验证；启用 Stage 0 挂起的 `#[ignore]` all-in e2e。

AIR 本体（14.9k 行约束族）不重写——"控制逻辑入 AIR"通过 micro-step 链化 + 真实生产者实现，而非扩写约束。

## 风险与边界

- Stage 1 改动集中在 accept-point 缝隙层，game_loop/表状态渲染回归面大——靠 Stage 0 测试 + shadow_e2e/full_hand 既有测试兜底。
- normalize trace 每步 clone 仅在证明 armed 时开启，不影响关证明的调试场景。
- 密码学方程、Blake 承诺重算（伴随 hash STARK）、状态根 SMT 锚定维持现有架构不扩scope。
