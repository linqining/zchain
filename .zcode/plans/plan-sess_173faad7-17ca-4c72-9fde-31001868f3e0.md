## 并行执行器改造方案（完整对象级并行 + WriteCaptureBackend）

### 设计总览

在 DAG 排序（`sort_commit_txs_r4m4`）与状态提交之间插入一层**波次化并行执行器**，替换 `executor.rs:492` `execute_block` 内部的串行 `for tx in txs` 循环。核心三件套：

1. **`WriteCaptureBackend`** —— 新的 `ObjectBackend` 实现：读委托给共享 `&ObjectDb`（`read` 本就是 `&self`，天然可并发），写进入线程私有 `ObjectWriteLog`，**零 SMT clone**。
2. **完整读写集** —— 扩展 `DispatchResult` 增加 `read_objects`，让 precompile（Game/TexasPoker）报告读集；补齐 `contract_id`、`outputs.ids`、`caller account` 等隐式读写。
3. **冲突检测 + 波次调度** —— 按读写集建冲突图，无冲突 tx 划入同一波次并发执行（rayon），波次间串行 merge。确定性等价于原串行语义。

关键 soundness 约束：**波次内并发执行，波次间按串行语义 merge**。任一波次内若发现实际读写集超出来时静态估计（precompile 运行后才知道读集），则该 tx 强制降级到下一波次串行重试——保证不会破坏串行等价性。

### 改动清单（7 项）

#### 1. 新增 `poker_l1/src/executor/write_capture.rs` — WriteCaptureBackend

```rust
/// 线程私有的写日志（替代 &mut ObjectDb 的写入侧）。
pub struct ObjectWriteLog {
    pub writes: Vec<WriteOp>,          // 有序写操作记录
    pub written_ids: HashSet<ObjectID>,// 写集（冲突检测用）
}

pub enum WriteOp {
    Create(Object),
    Update { id, actor, new_data },
    Transfer { id, actor, new_owner },
    Delete(ObjectID),
}

/// 读委托共享 &ObjectDb，写进入私有 log。
/// 注意：read 用 &ObjectDb（&self，可被多线程共享引用），
///       write 进 self.log（线程私有，无需锁）。
pub struct WriteCaptureBackend<'a> {
    shared: &'a ObjectDb,   // 共享只读快照基线
    log: ObjectWriteLog,
}

impl ObjectBackend for WriteCaptureBackend<'_> {
    fn read(&self, id) -> ... {
        // 1. 先查自己的 log（读自己写 / Read-Your-Writes）
        // 2. 未命中则委托 self.shared.read(id)
    }
    fn create/update/transfer/delete(&mut self, ...) {
        // 1. 校验（复用 ObjectDb 的所有权/碰撞校验语义）
        //    — create 碰撞检查需同时看 shared + log.written_ids
        //    — update/transfer/delete 需保证对象存在于 shared 或 log
        // 2. 记录到 self.log
    }
    fn state_root(&self) -> Hash {
        // 并行阶段不计算 state_root（merge 阶段由主库算）；
        // 提供一个基于 log 增量重算的实现，或 panic/标记（仅用于调试）。
    }
}
```

**为什么这样安全**：`ObjectBackend::read` 是 `&self`（已确认于 `object_backend.rs:32`），`&ObjectDb` 可被多个 worker 线程以共享引用持有（`ObjectDb` auto `Send+Sync`，`Arc<DB>` 可并发）。每个 worker 的写完全进私有 log，线程间不共享可变状态——无锁、无数据竞争。`ObjectWriteLog::apply_to(&mut ObjectDb)` 复用现有 `ObjectDb::create/update/...` 在 merge 阶段按序回放。

#### 2. 新增 `poker_l1/src/executor/schedule.rs` — 冲突检测 + 波次调度

```rust
/// 单 tx 的完整读写集（soundness 关键）。
pub struct ReadWriteSet {
    pub read:  HashSet<ObjectID>,   // objects 读
    pub write: HashSet<ObjectID>,   // objects 写
    pub account: Option<Address>,   // 调用者账户（nonce 链串行化）
}

/// 估计读写集（执行前静态可得的部分）。
/// 公式：
///   read  = tx.inputs ∪ {contract_id} ∪ precompile_read_hint
///   write = tx.outputs.ids ∪ contract_id（合约可能改自身？否—已确认不预载，
///           但保守纳入写集防 Soundness 漏洞）∪ created/modified（执行后回填）
///   account = Some(caller) 当 lane 需 nonce（Public/ForceSync）
pub fn estimate_rwset(tx, precompile_registry) -> ReadWriteSet;

/// 贪心波次划分：波次内任意两 tx 的 (read ∪ write) ∩ (read ∪ write) == ∅，
/// 且 account key 互不相同。
/// 与原串行确定性等价：第 k 波次的 tx 全部基于第 k-1 波次 merge 后的状态。
pub fn plan_waves(txs: &[Transaction], estimates: Vec<ReadWriteSet>) -> Vec<Vec<usize>>;

/// 判定两读写集是否冲突（用于运行时复核）。
pub fn conflicts(a: &ReadWriteSet, b: &ReadWriteSet) -> bool;
```

**确定性保证**：波次划分基于 `(rwset, tx_index)` 而非线程调度结果，故同样的输入永远得到同样的波次划分；波次内 tx 的结果聚合顺序按 `tx_index` 升序 merge，等价于串行。

#### 3. 改 `poker_l1/src/vm/precompile.rs` — `DispatchResult` 增加 `read_objects`

```rust
pub struct DispatchResult {
    pub created_objects: Vec<ObjectID>,
    pub modified_objects: Vec<ObjectID>,
    pub read_objects: Vec<ObjectID>,      // 新增（默认空，向后兼容）
    pub return_value: Vec<u8>,
}
```
- 更新所有 precompile 实现（`GamePrecompile`、`TexasPokerPrecompile` 等）在 `.read(id)` 时把 id 推入 `read_objects`。**为避免漏报导致并行 soundness 漏洞**，提供一个辅助宏 `recorded_read!(backend, id)` 或 wrapper，强制 precompile 经包装读。未改造的 precompile 在调度器里自动降级为串行（保守策略：`read_objects` 为空且 registry 标记"未审计"→ 串行）。

#### 4. 改 `poker_l1/src/executor.rs` — `execute_tx` 返回精确读写集 + 拆出 `prepare/commit`

把 `execute_tx_inner` 拆成三段，便于并行化：
- `prepare_tx(tx, &shared_db, &account_snapshot) -> Result<TxPlan>`：只读校验（limits/chain_id/签名/nonce/余额）+ 估计读写集。**纯函数，无副作用，可并发**。
- `run_tx(plan, &shared_db, &mut WriteCaptureBackend, &mut account_view)`：实际执行（rBPF/precompile/outputs），写进 WriteCaptureBackend。
- `commit_tx(receipt, write_log, &mut ObjectDb, &mut AccountStore)`：merge 阶段，串行。

`TxReceipt` 增加 `rwset: ReadWriteSet` 字段，运行后回填真实读写集（用于波次内复核：若真实读写集 ⊄ 估计读写集，标记 `unsequenced`，降级重跑）。

#### 5. 改 `execute_block` 主体 — 替换串行循环为波次并行

```rust
pub fn execute_block(env, txs, object_db: &mut B, account_store: &mut AccountStore)
    -> BlockExecutionOutcome
{
    // 1. prepare 阶段（可并发）：全部 tx 纯校验 + 估计读写集
    let plans = txs.par_iter().map(prepare_tx).collect();   // rayon

    // 2. 波次划分
    let waves = plan_waves(&plans);

    let mut receipts = vec![None; txs.len()];
    for wave in waves {
        // 3. 并发执行本波次：每个 worker 拿共享 &*object_db 构造 WriteCaptureBackend
        let shared: &ObjectDb = &*object_db;          // &self，安全共享
        let wave_logs: Vec<(usize, TxReceipt, ObjectWriteLog)> = wave
            .par_iter()
            .map(|&i| run_tx(&plans[i], shared, account_view_snapshot))
            .collect();

        // 4. 串行 merge（按 tx_index 升序）：写回 object_db + account_store
        for (i, receipt, log) in wave_logs {
            log.apply_to(object_db)?;                  // 复用现有 create/update
            apply_account_delta(account_store, &receipt);
            // 5. 运行时读写集复核：真实 ⊆ 估计则 ok，否则标记需重跑
            receipts[i] = finalize(receipt, &plans[i].rwset);
        }
    }
    // 6. 失败 tx / 降级 tx（复核未通过）→ 串行 fallback 重跑（等价于旧 execute_tx）
    finalize_outcome(receipts, object_db.state_root())
}
```

**账户 nonce 串行化**：同 caller 的多笔 tx 天然落在不同波次（account key 冲突），等价于串行推进 nonce——`validate_public_tx` 的严格 `nonce == account.nonce` 语义被保留。account_view_snapshot 在波次开始时按 caller 分片读取，避免 &mut AccountStore 跨线程。

#### 6. 新增 `poker_l1/src/executor/parallel_tests.rs` — 确定性/等价性测试

- **串行/并行等价性**：随机生成 N 笔 tx，分别跑旧 `execute_block_serial`（保留为测试 helper）与新 `execute_block`，断言 `state_root` 与每笔 receipt 完全一致。
- **冲突隔离**：构造两笔写同一 object 的 tx，断言落不同波次。
- **独立并行**：构造两笔写不同 object 的 tx，断言落同一波次且结果正确。
- **nonce 链保序**：同 caller 三笔 tx（nonce 0,1,2），断言分属三个波次，最终 nonce=3。
- **precompile 读集**：Game tx 的 rwset.read 包含 game_id；两笔 Game tx 若操作同一 game → 不同波次；不同 game → 同波次。

### 关键 soundness 保证（逐条）

| 风险 | 对策 |
|---|---|
| precompile 隐藏读未报告 → 并行漏冲突 | `DispatchResult.read_objects` + wrapper 强制记录；未审计 precompile 默认串行降级 |
| 真实读写集超出估计（合约动态访问） | 波次内运行后复核 `actual ⊆ estimated`，否则降级串行重跑 |
| 同账户 nonce 并发推进 | account key 纳入读写集，同 caller 必落不同波次 |
| merge 顺序不确定 | 波次内按 `tx_index` 升序 apply，等价串行 |
| SMT state_root 非确定性 | state_root 仅在 merge 后由主库计算一次，不在并发路径 |
| WriteCaptureBackend 并发数据竞争 | 读走共享 `&self`，写进线程私有 log，无共享可变状态 |
