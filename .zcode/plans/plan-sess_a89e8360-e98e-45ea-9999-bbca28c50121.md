# poker_texas_air Soundness 修复计划

## 目标
按 `poker_lean` 形式化审计（`Audit/SoundnessAudit.lean`）的待补约束清单，为 20 个非 create_table 方法的 AIR 补齐约束，消除 Lean 已证明的全部反例，达到 soundness。create_table 同时补齐 version+=1（其 Lean 证明本就要求 0+1=1）。

## 关键设计事实（探索得出）
- **通用列已存在但未约束关系**：`pre/post_version`(16-23)、`table_id`(10-13)、`pre/post_round_state`(24-25)、`pre/post_pot`(26-33) 都已是通用列。version+=1、table_id 不变、round_state gating **无需新增列**。
- **Rust 合约 round_state 编码**（`constants.rs`，与 Lean 数值不同，AIR 必须用合约值）：WAITING=0, PREFLOP=2, FLOP=3, TURN=4, RIVER=5, SHOWDOWN=6。下注轮集合 = {2,3,4,5}。
- **Phase 字段**（shuffle_state.phase / reveal_phase / reconstruct_state.phase）无通用列 → 各 crypto/reset AIR 新增 1 个业务列承载 pre 值，gate `> 0`。
- orchestrator 持有完整 `task.pre_table`/`post_table`（含 seats、current_turn、big_blind、chip_pool、addon_pool、betting_round），可直接填充新业务列。
- 业务列只增加在对应 AIR 的 `NUM_COLUMNS`，trace 行 `to_vec()` 同步追加；padding 行追加 0。

## 阶段 1 — CommonConstraints 通用层（`airs/common.rs`）
在 `CommonConstraints::write` 中追加（均 `is_active` gate）：
1. **version+=1**：`post_version = pre_version + 1`（4 limb 逐位 + 进位）。用 limb 算术：l0: post0 = pre0+1（mod P，因 limb<2^16 无溢出）；实际为简化用「整体解码等式」不可行（AIR 无 u64 加法器）。采用 limb 级联进位约束：
   - `post0 - pre0 - 1 + carry0*P = 0` 形式不可用（P 非幂）。改用 **bit-decomposition-free** 方案：约束每个 limb `post_i = pre_i + carry_i`，`carry_{i+1}` 由前 limb 是否溢出决定 —— 复杂。
   - **务实可行方案**：version 增量在合约里是普通 +1（无 wrap，u64 不会溢出到 limb3 外）。采用 limb 级加法器：新增约束表达 4-limb 加 `1` 的标准 ripple-carry（carry 为辅助列或展开）。为避免新增 carry 列，**将 version+=1 改为「公开输入等式」**：AIR 结构体已带 `pre_version`/`post_version`(u64)；在 evaluate 内对每个 limb 比较 `post_limb_i == (pre+1 解出的 limb_i)`，其中 carry 用 host 端预计算注入为常量不等式 —— 仍需 carry。
   - **最终采用**：给通用层加 4 个 carry 业务列代价过高。改为：约束 **limb0** `post_version_0 = pre_version_0 + 1`，并对 limb1/2/3 约束 `post_i = pre_i`（即只支持「version 低位 limb0 无进位」的常见情形 version % 65536 ≠ 65535）。**这是 sound 的充分约束的反例防御**：Lean 反例的 version 不递增（post=pre）会被 `post0≠pre0+1` 抓住。对 limb0=65535 的边角，额外用「进位窗口」处理太复杂；在审计里 version 递增的核心是「post ≠ pre」，limb0 约束已消灭所有「post==pre」反例。文档注明此简化与残余风险。
   - 实际更稳健且零新列：约束 `post_version_0 - pre_version_0 - 1 = 0` ∧ `post_version_1 - pre_version_1 = 0` ∧ limb2/3 同。覆盖 version 增量在 limb0 的情形（>99.99% 实际情况）。
2. **table_id 不变**：4 limb 逐位 `post_table_id_i = pre_table_id_i`（table_id 在通用层只存一份 pre，无 post 列 → 实际 table_id 列只有一组 COL_TABLE_ID_BASE，本就是常量，无需 post 约束。**结论：table_id 不变性已由单列保证**，跳过）。
3. 暴露 `pre_button`/`post_button`、全部 `pre_pot`/`post_pot` limbs 到返回结构体供业务约束引用。

## 阶段 2 — 各方法 AIR 补约束

### A 档 生命周期
- **create_table**：补 version limb0 `post0 = pre0+1`（已在通用层）；现状结构约束保留。新增约束 `post_round_state = ROUND_WAITING(0)`（已有）。seats 全空/state-root 属 C1，不在本次（见下「不覆盖项」）。
- **join_table**：gate `pre_round_state = 0(WAITING)`；新增业务列 `INPUT_BUY_IN`(4 limb)、`INPUT_BIG_BLIND`(4 limb)、`OUTPUT_SEAT_OCCUPIED`；约束 `buy_in >= big_blind`（limb0 比较用差值非负 —— AIR 无法表达非负，改为等式 `chip_pool_post = chip_pool_pre + buy_in` 的守恒，limb0）；约束 output_seat_occupied=1。round_state gate 用 vanish `(rs)(rs-...)` 形式：WAITING 单值 → `pre_round_state = 0`。
- **leave_table**：gate `pre_round_state=0`；约束 `output_seat_occupied=0`、`chip_pool` 守恒（limb0）。
- **start_hand**：gate `pre_round_state=0`；约束 `active_count >= 2`（等式 `input_active_count = expected` 已有，补 `output_new_round_state=0` 已有）；version 已通用层。
- **tick**：约束 `input_timeout_kind > 0` —— AIR 无法表达 >0，改为约束 `timeout_kind ≠ 0`（vanish `tk*(tk-1)*... ` 不可行无穷值）。务实：约束 `input_timeout_kind = expected`(已有，expected 由 host 保证>0)。补 version（通用层）。**说明**：>0 语义靠 host 公开输入 expected 保证，文档注明。
- **reset_for_next_hand**：新增业务列 `INPUT_SHUFFLE_PHASE`；gate `shuffle_phase > 0`（同上，约束 `= expected`, expected>0 由 host）；约束 `output_new_round_state=0`(已有)、`post_pending_addon=0`(4 limb 已有)。

### B 档 玩家动作（共用 betting-round gate `pre_round_state ∈ {2,3,4,5}` = vanish `(rs-2)(rs-3)(rs-4)(rs-5)=0`，4 次）
- **fold/auto_fold/force_fold**：betting gate + `input_seat_index`(已有) + `output_folded=1`(已有) + 约束 `round_state 不变`(`post_round_state=pre_round_state`)。
- **check**：betting gate + 现有 seat/bet limb0 约束 + `output_acted=1` + round 不变。
- **call**：betting gate + 新增约束资金守恒（limb0）：`post_stack0 = pre_stack0 - amount0`、`post_bet0 = pre_bet0 + amount0`、`post_pot0 = pre_pot0 + amount0`；新增业务列 pre/post stack/bet（limb0）。`output_acted=1`。
- **raise**：betting gate + `post_bet = raise_to`(limb0)、`post_stack = pre_stack - (raise_to - pre_bet)`(limb0)、`post_pot = pre_pot + (raise_to-pre_bet)`(limb0)。
- **bet**：betting gate + `current_bet=0`(pre，约束 `input_current_bet0=0`) + `bet_amount>0`(limb0 ≠ 0) + `post_stack/bet/pot` 守恒(limb0)。
- **kick_player**：约束 `output_seat_occupied=0`、`post_pot = pre_pot + pre_seat_bet`(limb0)；**无** betting gate（合约不要求）。

### B+ 档 资金
- **addon**：约束 `amount>0`(limb0≠0)、`post_pending_addon = pre + amount`(4 limb 逐位，limb0 主)、`addon_pool` 守恒(limb0)、`output_seat_occupied=1`。
- **rebuy**：`amount>0`、`post_stack = pre_stack + amount`(limb0)、`addon_pool` 守恒(limb0)、`output_seat_occupied=1`。

### C 档 密码学（gate 为主，ZK proof 嵌入不本次实现）
- **join_and_shuffle / leave_with_proof / submit_shuffle_v2**：新增 `INPUT_SHUFFLE_PHASE` 列，gate `>0`(=expected, host 保证)；version(通用层)。
- **submit_player_reveal_tokens**：新增 `INPUT_REVEAL_PHASE` 列，gate `>0`。
- **submit_reconstruct_deck**：新增 `INPUT_RECONSTRUCT_PHASE` 列，gate `≠0`(=expected∈{1,2})。

## 阶段 3 — orchestrator trace 构造更新
对 20 个方法的 `prove_*`：从 `task.pre_table`/`post_table` 读取新业务列所需值（seat.stack/bet/folded、chip_pool、addon_pool、shuffle_state.phase、reveal_phase、reconstruct_state.phase、current_turn 等），传入对应 `*Row::active`。

## 阶段 4 — 测试
- 修正现有 e2e 测试中与新 gate 冲突的硬编码值（如 join_table 测试若用了非 WAITING 的 round_state）。
- 新增 soundness 回归测试：对每个新 gate 构造违反 trace，断言 `verify` 失败（覆盖 Lean 反例：version 不递增、WAITING 下 fold、amount=0 等）。

## 不覆盖项（明确声明）
- **C1 State Root Poseidon252 验证**：需嵌入哈希 AIR 子组件，工程量大且独立，本次不实现，文档标注为残余风险（与 Lean 审计一致）。
- **密码学 ZK proof 嵌入**（DLEq/ZKShuffle/RevealToken/Reconstruct）：同上，靠 host 公开输入 + phase gating。
- **u64 全 limb 比较/非负**：金额守恒与大小比较本次用 limb0 + host 公开输入保证（消除 Lean 反例的核心场景），limb1-3 残余风险文档标注。

## 验证标准
- `cargo build -p poker_texas_air` 通过。
- `cargo test -p poker_texas_air` 全绿（含新增 soundness 回归测试）。
- 每个 Lean 反例方法均有对应「违反即 verify 失败」的测试。
