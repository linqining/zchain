1. 摘要

传统在线扑克把三件互相冲突的职责交给同一个服务器：发牌、保管筹码、审计公平。 本白皮书描述的系统把这三件事拆开——发牌由玩家协作完成，服务器只见密文； 筹码由链上金库托管，结算由可验证的状态转移驱动；审计由公开的 STARK 证明承担，任何第三方无需信任运营方即可复核。

结果是：作弊在协议层不可能，而不是在承诺层不被允许。

Inputs == proofs == Σpayouts + rake （守恒：逐手强制） plan.rake.total = Σ plan.pots[*].rake （分层自洽） finality: soft accepted → BFT ordered → proven → finalized/claimable

2. 威胁模型

2.1 运营方（Sequencer）

运营方假设是诚实但好奇（honest-but-curious）：它按协议排序与执行，但会尝试读取任何它能读到的信息。 协议对它的保证是——它在任何一手牌进行中都无法区分任意两张未揭示的牌，因为它从未拿到过对应的解密密钥。

2.2 合谋玩家

至多 t < n/2 个玩家可以合谋。超过该阈值时洗牌阶段的门限解密不再安全， 系统在牌桌层面拒绝开局而不是静默降级——这条在 §4.3 有对应的强制点。
